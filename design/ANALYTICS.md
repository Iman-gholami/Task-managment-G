# داشبورد مدیریتی (Analytics) — سند طراحی

این سند مرحله‌های ۵ تا ۱۴ فرایند طراحی را ثبت می‌کند: تحلیل پاسخ‌ها، KPI Framework، معماری اطلاعات، نمودارها، خروجی‌ها و UX Flow.
پیاده‌سازی در همین مخزن است: صفحه‌ها در `app/(app)/analytics/`، اجزا در `components/analytics/`، منطق محاسبه در `lib/analytics/` و داده سمت سرور در `lib/server/analytics.js`.

---

## ۱. تصمیم‌های نهایی (خلاصه پاسخ‌ها)

همه پاسخ‌ها همان پیشنهادهای مرحله نیازسنجی است، با یک تغییر مهم از طرف کارفرما:

> **فعلاً هیچ عدد ارزیابی (امتیاز، رتبه، برچسب «ضعیف/قوی») نمایش داده نمی‌شود. داشبورد فقط آماری است.** تیکت فقط به‌صورت تعداد شمرده می‌شود.

| موضوع | تصمیم |
|---|---|
| مخاطب | Security Manager (کل واحد) و SOC Manager (فقط SOC) کاربران اصلی؛ مدیران بالاتر گزارش یک‌صفحه‌ای می‌گیرند؛ کارشناس فقط آمار خودش و میانه تیم را می‌بیند |
| تصمیم‌ها | کشف زودهنگام مشکل، توزیع بار کار، نظارت عملیاتی SOC |
| صفحه اول | وضعیت کلی ← KPI ← هشدار و بینش ← روند ← تیم‌ها؛ بدون جدول افراد |
| ساختار | واحد ← تیم (SOC، طراحی و اتوماسیون، هوش تهدید) ← سطح (L1/L2/L3) ← کارشناس ← رکورد |
| جامعه آماری | تحلیلگران و مهندسان. مدیران در جدول افراد و مقایسه نیستند، ولی کار آن‌ها در جمع کل تیمشان حساب می‌شود. افراد غیرفعال در دوره‌های گذشته با برچسب «غیرفعال» دیده می‌شوند |
| ارزیابی | **ندارد.** نه امتیاز ترکیبی، نه رتبه‌بندی، نه چارک. جدول‌ها پیش‌فرض الفبایی‌اند؛ مدیر خودش می‌تواند بر اساس هر ستون مرتب کند |
| ارزش تسک | «حجم کار وزن‌دار» = جمع سطح پیچیدگی (ساده ۱، متوسط ۲، پیچیده ۳، پیشرفته ۴) |
| مقایسه تیم‌ها | سرانه (به ازای هر کارشناس)، توزیع کیفیت، درصد تحویل به‌موقع، سلامت صف کار |
| Target | فعلاً نیست. مرجع مقایسه: دوره قبل هم‌اندازه و میانه تیم |
| زبان و تقویم | فارسی، راست‌به‌چپ، تقویم شمسی، هفته از شنبه؛ اصطلاحات فنی (IOC، SOC، KPI) انگلیسی |
| بازه | پیش‌فرض ماه جاری شمسی؛ مقایسه هم‌اندازه (۱۴ روز اول مهر با ۱۴ روز اول شهریور) |
| داده | صفحه داخل همین سیستم با داده واقعی + «حالت نمایشی» با داده ساختگی برای جلسه |
| کتابخانه | ECharts از npm، همراه برنامه bundle می‌شود (بدون CDN، مناسب شبکه داخلی) |
| به‌روزرسانی | هنگام باز کردن صفحه + دکمه بارگذاری مجدد |
| دسترسی | Security Manager همه؛ SOC Manager فقط SOC؛ کارشناس فقط خودش |
| Drill-down | تا رکورد؛ پنل کشویی برای نگاه سریع و صفحه کامل برای هر نفر؛ مسیر راهنما |
| هشدار | سه سطح (بحرانی، نیازمند توجه، اطلاع)، آستانه‌ها در یک فایل تنظیمات |
| Insight | قاعده‌محور + آمار ساده (روند سه‌هفته‌ای، فاصله از میانه)؛ بدون LLM |
| خروجی | Excel چندشیتی، Excel هر کارشناس، CSV و PNG هر نمودار، چاپ و PDF، گزارش مدیریتی یک‌صفحه‌ای با یادداشت مدیر، حالت ارائه |
| دستگاه | اول دسکتاپ و لپ‌تاپ؛ تبلت کامل؛ موبایل خلاصه و هشدار |
| تم | همان چهار تم سیستم؛ چاپ همیشه روشن |

### چیزهایی که عمداً به فاز بعد رفت
| مورد | دلیل |
|---|---|
| امتیاز عملکرد، رتبه‌بندی، Top/Bottom Performers | تصمیم کارفرما: فعلاً فقط آمار. لایه داده آماده است و بعداً بدون تغییر ساختار اضافه می‌شود |
| Target دستی تیم‌ها | با «فقط آماری» هم‌خوان نیست و جدول و صفحه تنظیمات می‌خواهد. فعلاً دوره قبل و میانه تیم مرجع است |
| «بستن ماه» (ثابت کردن ارقام) | باید اول تصمیم گرفت تسکی که بعد از بستن ماه Reopen می‌شود در کدام ماه حساب شود. تا آن موقع هر خروجی Excel و PDF تاریخ تهیه و فیلترهایش را ثبت می‌کند تا قابل ردیابی باشد |
| فایل HTML مستقل قابل ایمیل | PDF و Excel همین نیاز را پوشش می‌دهند |
| PDF زمان‌بندی‌شده با ایمیل | سرویس سمت سرور و تنظیمات ایمیل می‌خواهد |

## ۲. تحلیل: مدیر با این داشبورد چه تصمیمی می‌گیرد؟

| سؤال مدیر | کجا جواب می‌گیرد | تصمیم |
|---|---|---|
| الان چیزی خراب است؟ | نوار وضعیت + هشدارهای صفحه اول | پیگیری فوری تسک معوق، شیفت‌لاگ بسته‌نشده، کار Blocked |
| صف کار بزرگ می‌شود یا کوچک؟ | نمودار «ورودی و خروجی کار» | تغییر اولویت‌ها، جلوگیری از ورود کار جدید، درخواست نیرو |
| بار کار عادلانه پخش شده؟ | «تسک باز به ازای هر نفر» در صفحه تیم‌ها | جابه‌جا کردن تسک‌ها |
| حجم کار از کار ساده می‌آید یا پیچیده؟ | ترکیب پیچیدگی | تنظیم تخصیص کار، برنامه آموزشی |
| کیفیت با افزایش حجم افت کرده؟ | بینش «حجم بالا، کیفیت پایین» + توزیع کیفیت | کم کردن فشار کار یا بازبینی فرایند |
| روتین‌های SOC انجام می‌شود؟ | صفحه عملیات SOC | پیگیری فعالیت‌هایی که مدام جا می‌مانند |
| شیفت‌ها منصفانه تقسیم شده‌اند؟ | توزیع نوع شیفت به ازای هر تحلیلگر | اصلاح برنامه شیفت |

### KPIهای سطح مدیریتی (صفحه اول)
1. تسک‌های تکمیل‌شده
2. حجم کار وزن‌دار
3. ساعت ثبت‌شده
4. درصد تحویل به‌موقع (همیشه با n)
5. صف کار باز (با تعداد معوق و Blocked)
6. بسته‌شدن شیفت‌لاگ SOC (با تعداد تیکت و IOC)

### KPIهای عملیاتی (صفحه‌های داخلی)
تسک‌های ایجادشده، میانه زمان انجام، دفعات برگشت تسک، ساعت به ازای تسک، تسک‌های در انتظار بازبینی، شیفت‌های برنامه‌ریزی‌شده به تفکیک نوع، درصد انجام روتین و هر فعالیت، IOC به ازای شیفت، تعداد تیکت، گزارش ترافیک، Issue.

### چه چیزی صفحه اول را شلوغ نمی‌کند
جدول افراد، فهرست تسک‌ها، جزئیات هر فعالیت روتین، توزیع اولویت، نمودارهای یک نفر. همه این‌ها با Drill-down در دسترس‌اند.

### شاخص‌هایی که گمراه می‌کنند (و چاره)
| شاخص | خطر | چاره در این داشبورد |
|---|---|---|
| ساعت ثبت‌شده | دستی وارد می‌شود؛ کار کند را بزرگ نشان می‌دهد | فقط «بار کار»؛ همیشه کنار تعداد تسک |
| تعداد تسک | تسک ساده و پیچیده یکسان حساب می‌شوند | همیشه کنار حجم وزن‌دار و ترکیب پیچیدگی |
| جمع کل تیم | فقط اندازه تیم را نشان می‌دهد | مقایسه تیم‌ها با سرانه |
| درصد با n کوچک | ۱ از ۱ یعنی ۱۰۰٪ | n کنار هر درصد؛ زیر حداقل نمونه «—» |
| مقایسه ماه ناقص با ماه کامل | اول هر ماه همه چیز «افت» دارد | مقایسه هم‌اندازه |
| IOC و تیکت خام | به تعداد شیفت بستگی دارد | «به ازای شیفت» کنار عدد خام |
| مقایسه L1 با L3 یا تحلیلگر با مهندس | نوع کار فرق دارد | هشدار در صفحه مقایسه وقتی نقش یا سطح فرق دارد |
| کیفیت | فقط برای تسک‌های تأییدشده ثبت می‌شود | توزیع کیفیت با تعداد، نه میانگین عددی |

### شاخص‌هایی که باید کنار هم بیایند
- تعداد تسک ↔ حجم وزن‌دار ↔ ترکیب پیچیدگی
- ورودی ↔ خروجی ↔ صف باز
- درصد به‌موقع ↔ تعداد تسک‌های دارای ددلاین
- IOC و تیکت ↔ تعداد شیفت
- حجم کار ↔ توزیع کیفیت

## ۳. KPI Framework

دوره‌ها به وقت تهران و تقویم شمسی‌اند. «دوره» یعنی بازه انتخاب‌شده تا امروز؛ آینده شمرده نمی‌شود.

### کار تسکی (همه کارشناسان)
| شاخص | تعریف | واحد |
|---|---|---|
| تسک تکمیل‌شده | تسک با وضعیت Done که تاریخ تأییدش در دوره است | تعداد |
| حجم کار وزن‌دار | جمع سطح پیچیدگی تسک‌های تکمیل‌شده (۱ تا ۴) | واحد |
| ساعت ثبت‌شده | جمع ساعت تسک‌های تکمیل‌شده | ساعت |
| ساعت به ازای تسک | ساعت ثبت‌شده ÷ تسک تکمیل‌شده | ساعت |
| تحویل به‌موقع | تکمیل‌شده‌هایی که تاریخ تأییدشان ≤ ددلاین است ÷ تکمیل‌شده‌های دارای ددلاین | ٪ (حداقل ۵ تسک) |
| میانه زمان انجام | میانه روز بین «شروع» و «تأیید» | روز |
| برگشت تسک | دفعات «Return for changes» در دوره | تعداد |
| سهم برگشتی | تکمیل‌شده‌هایی که حداقل یک بار برگشت خورده‌اند ÷ تکمیل‌شده | ٪ |
| ورودی | تسک‌هایی که در دوره ایجاد شده‌اند | تعداد |
| صف باز (اکنون) | همه تسک‌های انجام‌نشده و لغونشده (بک‌لاگ، برای انجام، در حال انجام، بازبینی، مسدود، برگشتی) | تعداد |
| معوق (اکنون) | باز (یا Backlog) با ددلاین گذشته | تعداد |
| Blocked (اکنون) | وضعیت Blocked؛ با مدت از آخرین Blocked شدن | تعداد، روز |
| در انتظار بازبینی | وضعیت Review؛ با مدت انتظار | تعداد، روز |
| توزیع کیفیت | تعداد تکمیل‌شده در هر سطح کیفیت | تعداد |
| ترکیب پیچیدگی | تعداد تکمیل‌شده در هر سطح پیچیدگی | تعداد |

### عملیات SOC (فقط تحلیلگران SOC)
| شاخص | تعریف |
|---|---|
| شیفت برنامه‌ریزی‌شده | ردیف‌های برنامه شیفت در دوره، به تفکیک صبح، تا ساعت ۲۰ و شب |
| ساعت شیفت | جمع ساعت نوع شیفت‌ها (۷٫۷۵، ۱۲٫۵، ۱۲) |
| بسته‌شدن شیفت‌لاگ | شیفت‌لاگ‌های کامل‌شده ÷ شیفت‌های گذشته (تا دیروز) |
| شیفت‌لاگ جامانده | شیفت گذشته بدون شیفت‌لاگ کامل‌شده |
| انجام روتین | فعالیت‌های انجام‌شده ÷ کل فعالیت‌های شیفت‌لاگ‌ها |
| IOC | جمع IOC ثبت‌شده در MISP؛ و IOC به ازای شیفت |
| تیکت | **فقط تعداد**؛ و تیکت به ازای شیفت |
| گزارش ترافیک | تعداد گزارش ترافیک روزانه انجام‌شده |
| Issue | تعداد فعالیت‌هایی که Issue ثبت کرده‌اند |

### سطح تیم
همه شاخص‌های بالا جمع اعضای تیم است. «سرانه» = جمع ÷ تعداد کارشناسان تیم در دوره (فعال یا دارای فعالیت در دوره). سهم بار: سهم پرکارترین نفر از صف باز تیم.

### مقایسه دوره‌ای
- **دوره قبل هم‌اندازه**: اگر دوره جاری تا امروز n روز گذشته، همان n روز اول دوره قبل.
- **همان دوره سال قبل**: همان تاریخ‌های شمسی یک سال قبل.
- تغییر درصدی فقط وقتی نمایش داده می‌شود که مقدار قبلی حداقل ۵ باشد؛ برای درصدها تغییر به «واحد درصد» نشان داده می‌شود.

## ۴. هشدارها و بینش‌ها

آستانه‌ها در `lib/analytics/config.js` است.

### هشدارها
| سطح | قاعده |
|---|---|
| بحرانی | تسک معوق با اولویت Critical یا High |
| بحرانی | تسک معوق بیش از ۷ روز |
| بحرانی | شیفت‌لاگ کامل‌نشده در ۳ روز گذشته |
| نیازمند توجه | تسک Blocked بیش از ۳ روز |
| نیازمند توجه | تسک در انتظار بازبینی بیش از ۲ روز |
| نیازمند توجه | ورودی بیشتر از خروجی در ۳ هفته کامل اخیر (صف رو به رشد) |
| نیازمند توجه | صف باز یک نفر ≥ ۲ برابر میانه تیم و ≥ ۵ |
| نیازمند توجه | تسک معوق دیگر |
| اطلاع | کارشناس بدون تسک باز (ظرفیت آزاد) |
| اطلاع | IOC به ازای شیفت ≥ ۳۰٪ کمتر از دوره قبل (حداقل ۱۰ شیفت) |

### بینش‌ها (آماری، بدون قضاوت درباره افراد)
- تغییر تسک‌های تکمیل‌شده واحد و هر تیم نسبت به دوره قبل
- روند سه‌هفته‌ای پیوسته (افزایشی یا کاهشی) در یک تیم
- حجم بیشتر ولی سهم کیفیت «عالی و خوب» کمتر
- تغییر خالص صف کار (ورودی منهای خروجی)
- تغییر درصد تحویل به‌موقع و میانه زمان انجام
- تمرکز صف کار روی یک نفر
- تغییر ترکیب پیچیدگی
- SOC: تغییر انجام روتین، فعالیتی که کمترین درصد انجام را دارد، روز غیرعادی تیکت (≥ ۳ برابر میانه)

هر بینش یک جمله، یک عدد و یک لینک به شواهد دارد. بینش‌ها بر اساس اندازه تغییر مرتب می‌شوند و ۴ مورد اول در صفحه اول می‌آید.

### نوار وضعیت
«بحرانی» اگر حداقل یک هشدار بحرانی باشد، «نیازمند توجه» اگر هشدار سطح دوم باشد، وگرنه «عادی». وضعیت از هشدارهای عملیاتی می‌آید، نه از ارزیابی افراد.

## ۵. معماری اطلاعات و Navigation

```
Analytics (منوی Insights در نوار کناری)
├── نمای کلی            /analytics            Executive Dashboard
├── تیم‌ها              /analytics/teams      مقایسه تیم‌ها؛ ?team= جزئیات تیم و سطح‌ها
├── کارشناسان           /analytics/people     جدول، توزیع، پنل کشویی
│   └── پروفایل          /analytics/people/<id>
├── مقایسه              /analytics/compare    افراد / تیم‌ها / دوره‌ها (حداکثر ۴)
├── روندها              /analytics/trends     روزانه تا سالانه، دوره در برابر دوره
├── عملیات SOC          /analytics/soc        شیفت، روتین، IOC، تیکت
├── هشدارها و بینش‌ها   /analytics/alerts
└── گزارش مدیریتی       /analytics/report     نسخه چاپی یک‌صفحه‌ای + یادداشت مدیر
```

- **سربرگ ثابت**: عنوان، برچسب دوره، زمان به‌روزرسانی، دکمه‌های خروجی و حالت ارائه.
- **زبانه‌ها** زیر سربرگ؛ با کیبورد قابل پیمایش.
- **نوار فیلتر ثابت (Sticky)**: بازه (پیش‌تنظیم‌ها + تقویم شمسی)، دوره مقایسه، تیم، سطح؛ دکمه «فیلترهای بیشتر» پنل کشویی نقش، اولویت، پیچیدگی، کیفیت و نوع شیفت را باز می‌کند.
- **همه فیلترها در URL** ذخیره می‌شوند؛ لینک هر نما قابل اشتراک است و زبانه‌ها فیلتر را حفظ می‌کنند.
- **مسیر راهنما (Breadcrumb)** در صفحه‌های عمقی: واحد › تیم › سطح › کارشناس.
- **دسترسی**: کارشناس فقط `/analytics/people/<id خودش>` را می‌بیند و میانه تیمش بی‌نام نمایش داده می‌شود.
- **حالت نمایشی**: دکمه «داده نمایشی» در سربرگ (`?demo=1`)؛ یک نوار کهربایی در کل صفحه‌ها اعلام می‌کند داده ساختگی است.

## ۶. صفحه‌ها و نمودارها

هر نمودار یک سؤال مدیریتی را جواب می‌دهد. همه نمودارها Tooltip، نمای جدول، دانلود CSV و PNG دارند.

### نمای کلی
| بخش | فرم | سؤال | چرا این فرم | تصمیم |
|---|---|---|---|---|
| نوار وضعیت | یک جمله + شمارش هشدار | وضعیت خوب است یا نه؟ | جواب در یک نگاه، بدون نمودار | ورود به هشدارها |
| ۶ کارت KPI | Stat tile + Sparkline + تغییر | هر شاخص نسبت به دوره قبل چطور است؟ | عدد خودش پیام است | ورود به روند همان شاخص |
| هشدارها و بینش‌ها | فهرست کوتاه | چه چیزی الان اقدام لازم دارد؟ | متن قابل اقدام | Drill-down به تسک یا نفر |
| ورودی و خروجی کار | دو خط هم‌واحد | صف کار رشد می‌کند؟ | روند زمانی دو سری با یک محور | اولویت‌بندی یا نیرو |
| تیم‌ها | جدول با میله سرانه و Sparkline | کدام تیم چه باری دارد؟ | چند شاخص هم‌زمان؛ جدول خواناتر است | ورود به جزئیات تیم |
| ترکیب کار | میله ۱۰۰٪ انباشته (پیچیدگی، کیفیت) | حجم از کار ساده آمده؟ کیفیت جابه‌جا شده؟ | سهم از کل برای دسته‌های ترتیبی | تخصیص کار |

### تیم‌ها
| نمودار | فرم | سؤال | تصمیم |
|---|---|---|---|
| سرانه تکمیل‌شده | میله افقی یک‌رنگ + خط میانه واحد | بازده سرانه هر تیم؟ | بررسی تیم دور از میانه |
| روند تیم‌ها | چندخطی (۳ رنگ دسته‌ای) | کدام تیم روند متفاوتی دارد؟ | بررسی علت |
| تسک باز هر نفر | نقطه‌ای به تفکیک تیم + میانه | بار کار متوازن است؟ | جابه‌جایی تسک |
| ترکیب پیچیدگی و کیفیت | میله ۱۰۰٪ انباشته | نوع کار تیم‌ها چه فرقی دارد؟ | تخصیص کار |
| جزئیات تیم | میله سطح‌ها (L1/L2/L3)، جدول اعضا | فرق سطح‌ها کجاست؟ | توزیع کار بین سطح‌ها |

### کارشناسان
- جدول الفبایی با همه شاخص‌ها، Sparkline و ستون‌های قابل مرتب‌سازی؛ جست‌وجو.
- «توزیع» یک شاخص انتخابی: نمودار نقطه‌ای افراد با خط میانه (برای دیدن پراکندگی، نه رتبه).
- کلیک روی نفر: پنل کشویی با خلاصه، روند کوتاه و فاصله از میانه تیم؛ دکمه «پروفایل کامل» و «Excel».
- پروفایل: کارت‌ها با تغییر نسبت به دوره قبل و میانه تیم؛ روند تسک‌ها و روند ساعت (دو نمودار جدا، بدون محور دوگانه)؛ ترکیب پیچیدگی و کیفیت؛ فهرست تسک‌های باز و تکمیل‌شده؛ برای تحلیلگر SOC تقویم حرارتی انجام روتین، IOC و تیکت روزانه.

### مقایسه
- حالت‌ها: کارشناسان، تیم‌ها، دوره‌ها؛ حداکثر ۴ مورد با رنگ ثابت.
- «میله‌های کوچک» (Small multiples): هر شاخص نمودار خودش با مقیاس خودش؛ بدون Radar (واحدهای متفاوت روی یک محور گمراه می‌کند).
- روند یک شاخص انتخابی برای همه موارد روی یک نمودار.
- هشدار وقتی نقش یا سطح موارد مقایسه فرق دارد.

### روندها
- شاخص، تفکیک (کل، تیم، سطح) و واحد زمانی (خودکار، روزانه، هفتگی، ماهانه، فصلی، سالانه) قابل انتخاب‌اند.
- دوره قبل به‌صورت خط خاکستری کم‌رنگ پشت خط اصلی (Period-over-Period).
- تقویم حرارتی روزانه تسک‌های تکمیل‌شده در ۱۲ ماه اخیر: الگوی روزهای هفته و ماه‌ها.
- صف باز در طول زمان (بازسازی از تاریخچه وضعیت‌ها).

## ۷. رنگ و نمایش داده

- **یک سری**: رنگ تأکید تم (`--viz-bar`، آخرین مقدار `--viz-bar-strong`).
- **دسته‌ای** (تیم‌ها، موارد مقایسه): ترتیب ثابت آبی، نارنجی، فیروزه‌ای، زرد (`--cat-1..4`). با `scripts/validate_palette.js` روی سطح کارت هر چهار تم بررسی شد: همه چک‌ها پاس است؛ در تم روشن دو رنگ زیر ۳:۱ است، پس همه نمودارها برچسب و نمای جدول دارند.
- **ترتیبی** (پیچیدگی، کیفیت، سطح L1 تا L3): طیف `--viz-1..4`.
- **حرارتی**: یک‌رنگ، از سطح کارت تا `--viz-4`.
- **وضعیت** (هشدار): فقط رنگ‌های وضعیت، همیشه با آیکن و متن.
- دوره قبل: خاکستری کم‌رنگ؛ خط‌ها ۲px؛ ستون‌ها حداکثر ۲۴px با گوشه گرد در انتها؛ بدون محور دوگانه؛ خط‌های شبکه کم‌رنگ و پیوسته.
- اعداد با رقم فارسی؛ ستون‌های عددی جدول هم‌تراز (tabular).
- متن نمودارها در قاب چپ‌به‌راست رسم می‌شود (تا موتور نمودار متن را درست بچیند) و هر برچسب در «embedding» راست‌به‌چپ قرار می‌گیرد تا متن ترکیبی فارسی و لاتین («۱ مهر»، «… در Splunk») درست خوانده شود. برچسب دسته‌ها سمت راست است و میله‌ها به سمت چپ رشد می‌کنند.

## ۸. Export Strategy

| خروجی | کجا | محتوا |
|---|---|---|
| Excel کامل | سربرگ › خروجی | شیت‌های: راهنما و تعریف شاخص‌ها، فیلترها، خلاصه، تیم‌ها، کارشناسان، روند، تسک‌ها (خام)، شیفت‌ها (خام)، تیکت روزانه (فقط تعداد). راست‌به‌چپ، سرستون ثابت، فیلتر خودکار، قالب عدد |
| Excel یک کارشناس | پنل کشویی و پروفایل | خلاصه، تسک‌های دوره، تسک‌های باز، روند، شیفت‌ها |
| Excel تیم‌ها | صفحه تیم‌ها | تیم‌ها، سطح‌ها، اعضا |
| CSV | هر نمودار و جدول | همان داده نمای جدول، UTF-8 با BOM برای باز شدن درست فارسی در Excel. نام فایل لاتین و همراه بازه شمسی است (`analytics-work-flow_1405-07-01_1405-07-14.csv`) چون برخی مرورگرها نام فارسی دانلود را نمی‌پذیرند |
| PNG | هر نمودار | تصویر ۲ برابر وضوح با پس‌زمینه روشن |
| PDF و چاپ | سربرگ › چاپ؛ گزارش مدیریتی | CSS مخصوص چاپ: تم روشن، بدون منو و فیلتر، نمودارهای برداری (SVG)، شکست صفحه کنترل‌شده |
| حالت ارائه | سربرگ | تمام‌صفحه، بدون نوار کناری، حروف بزرگ‌تر |

در همه خروجی‌ها دوره، فیلترها، زمان تهیه و «داده نمایشی» (در صورت فعال بودن) ثبت می‌شود. Excel سمت سرور با همان منطق محاسبه داشبورد ساخته می‌شود تا عددها یکی باشند.

## ۹. UX Flow

```
ورود مدیر → نمای کلی
  ├─ ۵ ثانیه اول: نوار وضعیت + ۶ KPI (تغییر نسبت به دوره قبل)
  ├─ هشدار «۴ تسک معوق با اولویت بالا در SOC» → فهرست تسک‌ها → صفحه تسک
  ├─ بینش «تیم X ۱۸٪ کمتر» → روندها با فیلتر همان تیم
  ├─ ردیف تیم → جزئیات تیم → سطح L2 → کارشناس (پنل کشویی) → پروفایل → Excel
  ├─ مقایسه: انتخاب ۲ تا ۴ نفر هم‌سطح → میله‌های کوچک + روند
  └─ گزارش مدیریتی → نوشتن یادداشت → چاپ یا ذخیره PDF
```

حالت‌ها: بارگذاری اول اسکلت (Skeleton) با ابعاد واقعی؛ بارگذاری مجدد نمودار قبلی را کم‌رنگ نگه می‌دارد؛ خطا فقط همان بخش را جایگزین می‌کند و «تلاش دوباره» دارد؛ حالت خالی توضیح می‌دهد چرا خالی است و یک اقدام پیشنهاد می‌کند (مثلاً «بازه بلندتر» یا «داده نمایشی»).
